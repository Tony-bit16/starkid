# 全部页面 UI 原型说明

> 本文件描述交互与布局。食材、本地菜谱、在线搜索/详情、食材匹配推荐、通知提醒、设置与关于页均已按此实现；
> 看板已通过 ContentProvider 读取主 App 真实食材，完成库存指标、分类饼图与 CSV 导出；导出写入公共下载目录并支持 FileProvider 打开。

## 1. 全局框架

### 1.1 主 App 导航

```text
                 ┌──────────────────────────────┐
                 │  MainActivity (singleTop)     │
                 │  FridgeApp / Scaffold         │
                 └──────────────┬───────────────┘
                                │
        ┌───────────────────────┼─────────────────────────┐
        │                       │                         │
┌───────▼────────┐     ┌────────▼────────┐       ┌────────▼──────────┐
│ ingredients    │     │ recipes         │       │ recipes/online    │
│ 食材库          │     │ 菜谱库           │       │ 在线搜索           │
└───────┬────────┘     └───────┬─────────┘       └────────┬──────────┘
        │                      │                          │
┌───────▼────────────┐  ┌──────▼─────────────────┐  ┌─────▼──────────────────┐
│ ingredients/detail │  │ recipes/detail/{id}    │  │ recipes/online/{mealId}│
│ /{ingredientId}     │  │ 菜谱详情                │  │ 在线菜谱详情            │
├────────────────────┤  ├────────────────────────┤  └────────────────────────┘
│ ingredients/new    │  │ recipes/new            │
│ 新增食材            │  │ 新增菜谱                │
└────────────────────┘  └────────────────────────┘
```

- 一级页（食材库/菜谱库/在线搜索）显示底部导航；详情/新增/设置/关于页隐藏底栏，顶部显示返回。
- 食材库顶栏“设置”进入 `settings`，设置页“关于”进入 `about`。
- 顶栏由 `FridgeApp` 统一提供，标题按当前 destination 切换。
- 系统返回键：详情/新增返回上一级；一级页退出 App。
- 切换底部 tab 使用 `saveState` / `restoreState`，保留各自滚动位置。
- 在线搜索失败只影响在线页；本地食材与菜谱仍可正常进入。

### 1.2 布局与视觉

| 项 | 规则 |
| --- | --- |
| 页面边距 | 水平 16dp，顶部 12dp，底部给底栏/导航条留 80dp |
| 卡片 | 使用主题 `Shapes.medium`（14dp）/`large`（18dp），1dp 边框，白底；不使用重阴影 |
| 圆角尺度 | 6 / 10 / 14 / 18 / 24dp，统一由 `FridgeTheme` 的 `Shapes` 提供 |
| 主色 | 深绿 `#2F6B4F`（新鲜/主按钮） |
| 强调色 | 橙 `#D9822B`（临期/提醒） |
| 错误色 | 红 `#BA1A1A`（过期/错误） |
| 字体 | 标题 22sp/600，正文 14–16sp，辅助 12sp |
| 触控 | 最小 48×48dp；列表整卡可点 |

### 1.3 统一四态

每个数据页面都必须覆盖：

| 状态 | 表现 | 动作 |
| --- | --- | --- |
| Loading | 居中进度圈/骨架卡片 + “正在加载…” | 无（或取消） |
| Empty | 图标 + 标题 + 解释 + 主按钮 | 新增/返回/去菜谱 |
| Error | 错误图标 + 中文原因 + “重试” | 重试；权限类给“去设置” |
| Success | 正常内容 | 各页交互 |

禁止：

- 白屏、只显示一个空白 `LazyColumn`。
- 异常直接崩溃或只打 Log。
- 用 `Success(emptyList())` 代替空态。

### 1.4 权限与降级矩阵

| 权限/能力 | 申请时机 | 拒绝/不可用 | UI 表现 |
| --- | --- | --- | --- |
| `POST_NOTIFICATIONS`（Android 13+） | 首次进入食材库先说明，用户同意后申请 | 不崩溃，提醒关闭 | 顶部提示条“通知权限未开启”；拒绝弹窗；永久拒绝显示“去设置” |
| CSV 写文件 | 点击“导出数据（CSV）”时 | 无数据/权限/空间/写入失败 | 无数据与失败弹窗；成功弹窗显示路径并可打开 |
| 跨 App Provider | 看板启动/刷新时 | `SecurityException`/无数据 | 错误态“请安装/更新冰箱管家，保持同一签名” |
| 存储权限 | 不需要 | — | 不申请 `READ/WRITE_EXTERNAL_STORAGE` |

### 1.5 交互与校验规范

- 三个一级列表（食材、菜谱、在线搜索）在有内容时支持下拉刷新；刷新保留旧内容，完成后自动收起，失败只弹窗/提示，不把列表替换成错误页。
- 所有页面跳转走安全导航；可恢复的导航异常由根 Scaffold 的 Snackbar 提示，不闪退。
- 新增食材/新增菜谱：首次提交前不显示字段错误；首次提交失败后，字段修改会即时重新校验并清除对应错误。
- 在线搜索：空输入或超过 40 字点击搜索时，在输入框下方即时提示；按钮不因空输入禁用。
- 表单错误统一使用 `supportingText` + `isError`，不只靠红框；保存中按钮显示进度并禁用。

## 2. 食材列表页

- 路由：`ingredients`
- 数据：`IngredientListViewModel.uiState`
- 目标：快速看到冰箱里有什么、哪些快过期，进入详情或新增。

### 2.1 布局

```text
┌────────────────────────────────────────────┐
│ 食材库                           [+ 新增]  │  TopAppBar
├────────────────────────────────────────────┤
│ ┌────────────────────────────────────────┐ │
│ │ 通知权限未开启                  [开启]  │ │  NotificationPermissionBanner
│ │ 到期提醒无法推送；食材状态仍可正常查看。 │ │
│ └────────────────────────────────────────┘ │
│ 共 3 条库存                                 │  Count
│ ┌────────────────────────────────────────┐ │
│ │ milk          [临期 · 还剩 2 天]       │ │  IngredientCard
│ │ Dairy · 1 L · 入库 11-12               │ │
│ └────────────────────────────────────────┘ │
│ ┌────────────────────────────────────────┐ │
│ │ garlic        [新鲜 · 还剩 30 天]      │ │
│ │ Seasoning · 1 head · 入库 11-14        │ │
│ └────────────────────────────────────────┘ │
│ ┌────────────────────────────────────────┐ │
│ │ yogurt        [已过期 · 12 天]         │ │
│ │ Dairy · 500 ml · 入库 11-01            │ │
│ └────────────────────────────────────────┘ │
├────────────────────────────────────────────┤
│        [食材]      [菜谱]      [在线搜索]   │  BottomBar
└────────────────────────────────────────────┘
```

### 2.2 组件

| 组件 | 内容/行为 |
| --- | --- |
| `TopAppBar` | 标题“食材库”；右侧“+ 新增”图标按钮 → `ingredients/new` |
| `NotificationPermissionBanner` | 未授权时显示“通知权限未开启”；按状态显示“开启”/“去设置”；已授权不占位 |
| `Count` | “共 N 条库存”文字 |
| `IngredientCard` | 名称、分类、数量+单位、剩余天数、`FreshnessPill`；当前实现 |
| `FreshnessPill` | 绿“新鲜”/橙“临期”/红“已过期”；阈值由 `ExpiryCalculator` 统一 |
| 空态 | 冰箱图标 + “冰箱还是空的” + “点击右上角新增…” |
| 错误态 | “食材加载失败” + 原因 + “重试” |
| 加载态 | 居中进度圈 + “正在加载…” |

### 2.3 交互

当前已实现：点击卡片进详情、右上角新增、计数展示、三色标签、四态与重试、通知权限提示、下拉刷新。

1. 点击卡片 → `ingredients/detail/{id}`。
2. 点击“+ 新增” → `ingredients/new`。
3. 点击权限条“开启”：首次先说明，已说明过则直接请求系统权限；拒绝后弹窗可再次申请。
4. 永久拒绝/通知总开关关闭：按钮变“去设置”，跳转应用通知设置；返回后 `ON_RESUME` 自动刷新。
5. 下拉刷新：仅在有内容时启用，顶部出现 Material3 刷新指示器；完成后自动收起，失败保留旧列表并由 Snackbar 提示。
6. 长按卡片：本轮不做批量操作；不要放隐藏手势。
7. 删除入口不放列表页，避免误触；删除在详情页二次确认。

### 2.4 状态

| 状态 | 触发 | 展示 |
| --- | --- | --- |
| Loading | 首次订阅/重试 | 居中进度圈 + “正在加载…” |
| Empty | 数据库 0 条 | 引导新增 |
| Error | 查询异常 | 错误文案 + 重试 |
| Success | 有数据 | 概览 + 列表 |

### 2.4 系统通知

- 渠道：`expiry_reminder`，默认重要性；不响铃轰炸，不使用全屏 Intent。
- 标题：“有 N 种食材即将过期”；正文逐条“• 名称：今天到期 / 明天到期 / 还剩 N 天”。
- 多条临期合并为一条；同一天多次检查不重复叠加通知。
- 点击：打开或复用 `MainActivity`，清理详情/新增返回栈后落到食材库。
- 无临期时取消旧通知，避免“已经吃完还提醒”。
- 已过期食材不推送，只在列表用红色“已过期”标签提示。

### 3.2 组件与交互

| 组件 | 行为 |
| --- | --- |
| 返回 | 返回食材列表，保留滚动位置 |
| 编辑 | 当前页切换为编辑态，复用 `IngredientForm`；保存成功后回到只读态并显示 Snackbar |
| 删除 | 底部“删除”按钮；不提供额外“更多”菜单 |
| 保质期进度条 | 目标能力：`elapsed / shelfLifeDays`；当前以“剩余 N 天”文字表达 |
| 匹配提示卡 | 食材详情不展示匹配；可到菜谱库「推荐菜谱」查看相关结果 |
| 删除按钮 | `AlertDialog`：“删除后无法恢复；菜谱定义与食材品类不会受影响。” 取消/删除 |
| 删除成功 | 返回列表，列表通过 Room Flow 自动刷新（不额外弹 Snackbar） |
| 删除失败 | 留在本页，Snackbar 错误，可重试 |

### 3.3 状态

| 状态 | 展示 |
| --- | --- |
| Loading | 头部骨架 + 信息行骨架 |
| Empty | “这批食材已被删除” + “返回列表” |
| Error | 错误文案 + 重试；若 `NotFound` 用空态 |
| Success | 上述内容 |

### 3.4 边界

- 数量为 0：仍可查看，状态显示“已用完”，删除按钮可用。
- 已过期：进度条红色，顶部显示“已过期”，不阻止查看。
- 保质期天数很大：进度条仍按比例，文字显示实际天数。

## 4. 新增食材页

- 路由：`ingredients/new`
- 数据：`AddIngredientViewModel.formState`
- 目标：最少输入完成一次入库，实时看到到期日，保存失败不丢表单。

### 4.1 布局（当前实现）

```text
┌────────────────────────────────────────────┐
│ [←] 新增食材                                │
├────────────────────────────────────────────┤
│ ┌ 基本信息 ──────────────────────────────┐ │
│ │ 名称  [例如：番茄                    ] │ │
│ │ 分类  [例如：蔬菜 / 蛋奶 / 乳制品    ] │ │
│ └────────────────────────────────────────┘ │
│ ┌ 库存信息 ──────────────────────────────┐ │
│ │ 入库时间 [2026-11-12          选择]    │ │
│ │ 保质期天数 [正整数，单位：天         ] │ │
│ │ 数量 [例如：3]      单位 [个/克/袋]    │ │
│ └────────────────────────────────────────┘ │
│ [              保存食材                  ] │
│ 数量支持小数（如 0.5 kg）；入库时间保存为  │
│ 当天 00:00 的时间戳。                      │
└────────────────────────────────────────────┘
```

- 新增页顶栏只提供返回，不在顶栏放保存按钮。
- 表单字段使用 `OutlinedTextField`，字段错误通过 `supportingText` + `isError` 展示。

### 4.2 字段与校验

| 字段 | 控件 | 规则 | 错误文案 |
| --- | --- | --- | --- |
| 名称 | 单行文本框 | 必填，trim 后 1–30 字 | “请输入食材名称” / “名称不能超过 30 个字符” |
| 分类 | 单行文本框 | 必填，trim 后 1–20 字 | “请输入食材分类” / “分类不能超过 20 个字符” |
| 入库时间 | 日期选择器 | 默认今天；不得晚于当前时间 | “入库时间不能晚于当前时间” |
| 保质期 | 数字键盘 | 必填，整数 1–36500 | “请输入整数天数” / “保质期不能超过 36500 天” |
| 数量 | 小数键盘 | 必填，> 0，≤ 1,000,000 | “数量必须大于 0” / “数量超出可记录范围” |
| 单位 | 单行文本框 | 必填，trim 后 1–10 字 | “请输入数量单位” / “单位不能超过 10 个字符” |

- 名称不弹品类选择器；保存时由 Repository 按规范化名称自动复用/创建 `IngredientType`。
- 表单不展示预计到期卡；保存成功后列表/详情按 `storedAt + shelfLifeDays` 计算并展示。
- 数量输入只过滤数字与一个小数点，允许 `0.5` 这类小数。

### 4.3 交互

1. 保存：字段校验 → 按钮进入 loading/禁用 → Repository 保存。
2. 成功：返回列表，列表通过 Room Flow 自动刷新；不额外弹 Snackbar。
3. 失败：留在表单，顶部错误横幅 + 字段错误；不清空输入。
4. 返回：直接返回列表；当前不做“放弃编辑”二次确认。
5. 日期选择：Material3 `DatePickerDialog`，只选日期，不选时间。
6. 键盘：系统默认行为；保存时由页面导航收起。

### 4.4 状态

- 初始：空表单，保存按钮可点击；点击后逐字段校验。
- 校验失败：字段级错误提示，焦点留在表单。
- 保存中：保存按钮转圈并禁用，防重复提交。
- 保存失败：恢复可编辑，顶部错误横幅 + 字段错误。

## 5. 菜谱列表页

- 路由：`recipes`
- 数据：`RecipeListViewModel.uiState`
- 目标：浏览本地菜谱，进入详情或手动新增；在线搜索从底部独立页签进入。

### 5.1 布局

```text
┌────────────────────────────────────────────┐
│ 菜谱库                              [新增]  │
├────────────────────────────────────────────┤
│ [全部菜谱] [推荐菜谱]                       │  FilterChip
│ 推荐 1 道菜谱                               │
│ ┌────────────────────────────────────────┐ │
│ │ (S) Spicy Arrabiata Penne          3 步 │ │  RecipeCard
│ │     [缺少多种食材] 1/8 已备齐           │ │
│ │     缺少：penne rigate、olive oil…      │ │
│ └────────────────────────────────────────┘ │
│                                            │
├────────────────────────────────────────────┤
│      [食材库]    [菜谱库]    [在线搜索]      │
└────────────────────────────────────────────┘
```

### 5.2 组件与交互

| 组件 | 行为 |
| --- | --- |
| `FilterChip` | “全部菜谱 / 推荐菜谱”；切换只重排/重算本地数据，不跳页 |
| `RecipeCard`（全部） | 首字、菜名、食材摘要（最多 2 行）、步数；整卡可点 |
| `RecipeCard`（推荐） | 额外显示等级徽标、`已备齐 N/M`、全部缺少食材（红色） |
| 点击卡片 | → `recipes/detail/{id}` |
| 新增入口 | 顶栏右侧“新增” → `recipes/new` |
| 在线搜索 | 底部第三个 Tab → `recipes/online` |
| 空态（全部） | “还没有菜谱” + “点击右上角‘新增’，记录第一道菜谱。” |
| 空态（推荐/无菜谱） | “还没有本地菜谱” + “先到在线搜索保存…” + “去在线搜索” |
| 空态（推荐/无库存） | “冰箱里还没有食材” + “添加食材后查看推荐菜谱” + “去添加食材” |
| 空态（推荐/无匹配） | “暂时没有可推荐的菜谱” + 提示补充食材 |
| 错误态 | “加载失败” + 中文原因 + 重试 |
| 加载态 | 居中进度圈 + “正在加载…” |

### 5.3 状态

- 全部：按菜名排序，空列表映射为 `Empty`。
- 推荐：同时观察菜谱与库存；无菜谱/无库存/无匹配分别给出对应空态与动作。
- 匹配在 `Dispatchers.Default` 计算；切换筛选不会阻塞主线程，结果未变时不闪加载态。
- 本地菜谱关键词搜索仍未实现；在线搜索在独立 Tab。

## 6. 菜谱详情页

- 路由：`recipes/detail/{recipeId}`
- 数据：`RecipeDetailViewModel.uiState`
- 目标：看清需要什么、还差什么、怎么做。

### 6.1 布局

```text
┌────────────────────────────────────────────┐
│ [←] 菜谱详情                                │
├────────────────────────────────────────────┤
│ ┌────────────────────────────────────────┐ │
│ │ 番茄炒蛋                                │ │  HeaderCard
│ │ 3 种食材 · 3 个步骤                     │ │
│ │ [缺少 1 种食材] 2/3 种食材已备齐        │ │
│ └────────────────────────────────────────┘ │
│ 所需食材                                    │
│ ┌────────────────────────────────────────┐ │
│ │ 西红柿        2 个        [已有]        │ │  IngredientRow
│ │ 鸡蛋          3 个        [缺少]        │ │
│ │ 葱            1 根        [缺少]        │ │
```

## 13. 交互与可访问性检查

- 所有图标按钮有 `contentDescription`；颜色不是唯一状态表达（同时有文字）。
- 列表项点击区域 ≥ 48dp；删除按钮与“保存”保持足够间距。
- 表单错误用 `supportingText` + `isError`，不只靠红框。
- 字体缩放 200% 时表单不截断；长文本可换行。
- 深色模式：使用主题语义色，不硬编码白底黑字；`StateLayouts` 与表单均走 MaterialTheme 颜色。
- 横屏/平板：内容最大宽度 720dp，避免表单过宽。
- 动效：页面切换使用默认 Navigation 动画；不要为列表做复杂共享元素动画。
